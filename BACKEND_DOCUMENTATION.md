## 1. Overview

Poshu Sheba AI is a FastAPI service that provides preliminary animal-health guidance for farmers and pet owners in Bangladesh. A client submits a written description, one or more images, and/or a Bengali audio recording describing an animal's symptoms; the service returns a Bengali-language guidance response generated by a Google GenAI model, grounded against a local curated disease knowledge base. The service also provides user accounts, 30-day login sessions, and private storage of previously generated responses.

**This service provides preliminary guidance only. It is not a diagnostic tool and is not a substitute for care from a licensed veterinarian, especially in emergencies.**

## 2. Tech Stack

| Layer | Technology |
| --- | --- |
| Web framework | FastAPI |
| Language | Python |
| Database | MongoDB |
| AI / language model | Google GenAI API (Gemini API), currently configured against a Gemma model — see [Operational Notes](#13-operational-notes) |
| Speech-to-text | `faster-whisper` (`small` model), local inference |

| Auth | Bearer tokens (session-based, hashed server-side) |
| Password hashing | `scrypt` (salted) |

## 3. Architecture

```text
Client request
    │
    ├── Account / saved-response requests ──► FastAPI ──► MongoDB
    │
    └── Animal-health question ──────────────► FastAPI
                                                  ├── Audio (if supplied) ──► FFmpeg + Whisper (local transcription)
                                                  └── Text / images / structured intake ─► Google GenAI (Gemini API)
                                                                                              │
                                                  ◄───────────────────────────────────────────┘
                                                     Bengali veterinary guidance
```

Request flow for `/generate`:

1. Client submits `info` (structured JSON), `text`, `images`, `audio`, and/or `animal_type` as `multipart/form-data`.
2. If `audio` is present, it is converted to 16 kHz mono WAV and transcribed to Bengali text locally.
3. `info` is parsed from JSON; its values plus `text` and the audio transcript are combined and matched, by keyword, against a local disease knowledge base (optionally filtered by `animal_type`).
4. Any matched knowledge-base entries, the structured `info` data, `text`, the audio transcript, and any images are assembled into a single prompt and sent to the Gemini API.
5. The model's Bengali-language response is returned to the client as-is.

## 5. Getting Started

### 5.1 Prerequisites

- Python 3.x with the packages listed in `requirements.txt`
- A reachable MongoDB deployment
- A valid Google Gemini API key
- FFmpeg available on the host (required for audio conversion)
- Network access from the backend to MongoDB and the Gemini API endpoint

### 5.2 Installation

```bash
pip install -r requirements.txt
```

### 5.3 Running the service

Create a `.env` file in the repository root (see [Configuration](#6-configuration--environment-variables)), then start the API from the `Backend` directory:

```bash
uvicorn main:app --reload
```

By default the API is available at `http://127.0.0.1:8000`. Interactive API docs (Swagger UI) are available at `/docs` while the service is running.

On startup, the application verifies the MongoDB connection and creates required indexes. **Startup fails immediately** if either MongoDB environment variable is missing or MongoDB cannot be reached.

## 7. Authentication

Authentication is bearer-token based, backed by server-side sessions:

1. A client registers via `POST /register` and logs in via `POST /login`.
2. `POST /login` returns an `access_token` valid for 30 days. **This token is returned only once, at login** — it is never re-displayed and the server stores only its hash.
3. Protected endpoints require the header:

```http
Authorization: Bearer <access_token>
```

4. On each authenticated request, the server hashes the presented token and looks up the matching session. Expired sessions are rejected and removed on encounter; MongoDB's TTL index also removes them automatically in the background.

`POST /generate` does **not** require authentication. `POST /save-response` and `GET /saved-responses` do.

## 9. Database Schema

MongoDB, three collections:

| Collection | Stored fields | Indexes |
| --- | --- | --- |
| `users` | name (or null), canonical phone number, salted password hash, address, email (or null, default null), profile_picture_url (or null, default null), farms (array, default `[]`), creation time | Unique `phone_number` |
| `sessions` | canonical phone number, SHA-256 token hash, creation time, expiry time | Unique `token_hash`; TTL on `expires_at` |
| `saved_responses` | owner phone number, response text, creation time | Compound `phone_number`, `created_at` |

Passwords are hashed with salted `scrypt`. Plaintext passwords and bearer tokens are never stored — only the `scrypt` hash and the SHA-256 token hash, respectively.

Health check.

**Auth:** none

**Response `200 OK`:**

{"message":"Poshu Sheba AI API is running"}

### 10.2 `POST /register`

Creates an account. No phone verification is currently performed.

**Auth:** none

**Request body:**

```json
{
  "name": "Optional name",
  "phone_number": "01712345678",
  "password": "at-least-8-characters"
}
```

**Response `201 Created`:**

```json
{"message":"User registered successfully","user_id":"..."}
```

**Errors:** `409` if the phone number already has an account; `422` on validation failure.

---

### 10.3 `POST /login`

Authenticates a registered user and creates a 30-day bearer-token session.

**Auth:** none

**Request body:**

```json
{
  "phone_number": "01712345678",
  "password": "at-least-8-characters"
}
```

**Response `200 OK`:**

```json
{
  "access_token": "...",
  "token_type": "bearer",
  "expires_at": "2026-07-18T00:00:00+00:00"
}
```

The `access_token` is returned only in this response. Use it as `Authorization: Bearer <access_token>` on protected routes.

**Errors:** `401` on invalid credentials; `422` on validation failure.

### 10.4 `POST /generate`

Generates preliminary Bengali veterinary guidance.

**Auth:** none

**Content type:** `multipart/form-data`

At least one of `info`, `text`, `images`, or `audio` is required.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `info` | text (JSON-encoded string) | conditional* | Structured intake collected via mandatory frontend form fields: animal age, fever status, stool/urine status. Sent as a form field whose value is a JSON string. |
| `text` | text | conditional* | Freeform written description of the animal's condition |
| `images` | repeatable file field | conditional* | One or more images for visual context |
| `audio` | file | conditional* | Bengali audio recording describing the issue |
| `animal_type` | text | no | Animal selector (`cow`, `goat`, `chicken`, or `duck`) used to filter matched disease profiles |

\* At least one of `info`, `text`, `images`, `audio` must be present.

**`info` format:**

```json
{
  "age": 3,
  "fever": "উচ্চ তাপমাত্রা",
  "stool_urine": "স্বাভাবিক"
}
```

`age` is a JSON number; `fever` and `stool_urine` are Bengali strings drawn from a fixed set of frontend selectbox options (not arbitrary free text), which keeps values consistent for keyword matching. The backend parses this field with `json.loads()` immediately on receipt; if `info` is present but not valid JSON, the request is rejected (see [Error Handling](#11-error-handling)).

**Example request:**

```bash
curl -X POST http://localhost:8000/generate \
  -F 'info={"age": 3, "fever": "উচ্চ তাপমাত্রা", "stool_urine": "স্বাভাবিক"}' \
  -F 'text=গরুটা খাচ্ছে না তিন দিন ধরে' \
  -F 'animal_type=গরু' \
  -F 'images=@cow1.jpg' \
  -F 'audio=@note.m4a'
```

**Response `200 OK`:**

```json
{"response":"AI-generated Bengali veterinary guidance"}
```

**Processing notes:**

- Images are base64-encoded and passed to the model as-is.
- Audio is converted to 16 kHz mono WAV with FFmpeg, then transcribed locally with the `faster-whisper` `small` model.
- Before querying the Gemini API, the backend combines the parsed `info` values, `text`, and the audio transcript, then performs case-insensitive substring matching against the symptom list in `Backend/data/disease_knowledge_base.json` (filtered by `animal_type` if provided). Matching entries are formatted in Bengali as a grounding block and appended to the prompt.
- If no disease entries match, the model falls back to general reasoning but is instructed to explicitly state that its answer is a general assessment, not a confirmed diagnosis.
- The model is instructed to respond only in Bengali, stay within animal-health topics, use plain language, describe likely causes and immediate at-home steps, flag urgent warning signs, and recommend veterinary consultation when appropriate.

**Errors:** `400` if no usable input is supplied or `info` is not valid JSON; `502` if the Gemini API call fails.

### 10.5 `POST /save-response`

Saves one generated response for the authenticated user.

**Auth:** required — `Authorization: Bearer <access_token>`

**Request body:**

```json
{"response":"Text of the generated response"}
```

**Response `201 Created`:**

```json
{"message":"Response saved successfully","response_id":"..."}
```

**Errors:** `401` if the token is missing/invalid/expired; `422` on validation failure (e.g. empty or oversized response text).

---

### 10.6 `GET /saved-responses`

Returns the authenticated user's saved responses, newest first.

**Auth:** required — `Authorization: Bearer <access_token>`

**Response `200 OK`:**

```json
{
  "phone_number": "+8801712345678",
  "responses": [
    {
      "response_id": "...",
      "response": "Saved AI guidance",
      "created_at": "2026-07-18T00:00:00+00:00"
    }
  ]
}
```

**Errors:** `401` if the token is missing/invalid/expired.

## 11. Error Handling

Error responses use FastAPI's standard `detail` field. Some messages are intentionally written in Bengali so they can be surfaced directly in the user interface.

| Status | Meaning |
| --- | --- |
| `400` | `/generate` received no `info`, `text`, image, or audio input, or `info` was not valid JSON |
| `401` | Login failed, or a protected request has no valid, unexpired bearer token |
| `409` | The phone number already has an account |
| `422` | Request body/fields fail validation |
| `500` | Audio could not be converted or transcribed |
| `502` | The Gemini API returned an error while producing a response |

## 12. Security Considerations

- Passwords are hashed with salted `scrypt`; plaintext passwords are never stored.
- Bearer tokens are never stored in plaintext — only a SHA-256 hash of each token is persisted, and the raw token is shown to the client exactly once, at login.
- Sessions expire after 30 days; expired sessions are rejected on use and cleaned up both reactively and via MongoDB's TTL index.
- `.env` files and database credentials must be kept out of version control.
- The application currently has **no CORS configuration**. A browser client on a different origin will need an explicit CORS policy added before it can call this API.
- Upload size and file-type validation for `images` and `audio` should be enforced at the deployment boundary (e.g. reverse proxy or gateway) if the service is exposed publicly, since the application layer does not currently restrict these.

## 13. Operational Notes

- **Model latency and "thinking" behavior:** `Backend/services/ai.py` currently targets a Gemma-family model (`models/gemma-4-26b-a4b-it`) via the Gemini API. Gemma 4 has a built-in, enabled-by-default internal reasoning ("thinking") step, which can noticeably increase response latency. As of this writing, the Gemini API's standard `thinkingConfig` controls (`thinkingBudget`, `includeThoughts`) are not honored for Gemma 4 models served through this endpoint — `thinkingBudget` is rejected outright, and `includeThoughts: false` is accepted but silently ignored, with thought tokens still generated and billed. There is currently no supported way to fully disable thinking for this model through the hosted Gemini API. If latency becomes a problem, mitigations include capping `max_output_tokens`, switching to a smaller Gemma 4 variant, moving this specific call to a native Gemini model (e.g. `gemini-2.5-flash` with `thinking_budget=0`, which does support disabling thinking), or self-hosting the model where the thinking token can be controlled directly.
- The audio/transcription pipeline (FFmpeg + local Whisper) runs on the same host as the API and is resource-intensive; capacity planning should account for concurrent transcription and model-generation load.
- Audio transcripts are explicitly flagged to the model as Bengali speech transcribed via ASR, since phonetic similarity can cause Bangla speech to be mis-rendered in Hindi script/wording.
