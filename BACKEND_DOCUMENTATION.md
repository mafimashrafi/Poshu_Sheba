# Poshu Sheba AI — Backend Documentation

## Overview

Poshu Sheba AI is a FastAPI service for preliminary animal-health guidance in Bangladesh. It accepts a written description, animal images, or a Bengali audio recording and returns a Bengali response generated by the Google GenAI Gemini API (grounded using a local curated disease knowledge base). The service also supports user accounts, 30-day login sessions, and private saved responses.

This service provides guidance only; it is not a substitute for diagnosis or emergency veterinary care.

## Service architecture

```text
Client request
    │
    ├── Account and saved-response requests ──► FastAPI ──► MongoDB
    │
    └── Animal-health question ──────────────► FastAPI
                                                  ├── Audio (if supplied) ──► FFmpeg + Whisper
                                                  └── Text/images ─────────► Google GenAI (Gemini)
                                                                              │
                                                  ◄──────────────────────────┘
                                                     Bengali veterinary guidance
```

The backend is organised as follows:

| Location | Responsibility |
| --- | --- |
| `Backend/main.py` | FastAPI application factory (creates app, sets lifespan, includes routers, and root `/` check) |
| `Backend/core/config.py` | Environment configuration loading (`.env` path parsing) |
| `Backend/core/security.py` | Password hashing, password verification, and session-token hashing |
| `Backend/db/mongodb.py` | MongoDB connection lifespan management, index creation, and saved responses database helpers |
| `Backend/models/user.py` | Pydantic models for user registration (`UserRegisterRequest`) and login (`LoginRequest`) |
| `Backend/models/response.py` | Pydantic model for saving a response (`SaveResponseRequest`) |
| `Backend/routers/auth.py` | Endpoints for user registration (`/register`) and login (`/login`) |
| `Backend/routers/responses.py` | Endpoints for saving and retrieving generated guidance responses (`/save-response`, `/saved-responses`) |
| `Backend/routers/generate.py` | Endpoint for veterinary guidance generation (`/generate`) |
| `Backend/services/audio.py` | Audio conversion using FFmpeg and transcription using faster-whisper |
| `Backend/services/ai.py` | Google GenAI (Gemini) client wrapper containing system prompts, model config, and disease knowledge base symptom matching logic |

## Requirements

- Python environment with the packages in `requirements.txt`
- A reachable MongoDB deployment
- A valid Google Gemini API key configured in `.env`
- Network access from the backend to MongoDB and the Gemini API endpoint

Create a `.env` file in the repository root:

```env
MONGODB_URI=<your MongoDB connection string>
MONGODB_DB=<database name>
```

Start the API from the `Backend` directory:

```bash
uvicorn main:app --reload
```

By default, the API is available at `http://127.0.0.1:8000`. FastAPI’s interactive reference is available at `/docs` while the service is running.

On startup, the application checks the MongoDB connection and creates the required indexes. Startup stops immediately if either MongoDB environment variable is missing or MongoDB cannot be reached.

## API reference

### `GET /`

Returns a basic availability message. This route is intended for simple health checks.

```json
{"message":"Poshu Sheba AI API is running"}
```

### `POST /register`

Creates an account. No phone verification is currently performed.

Request body:

```json
{
  "name": "Optional name",
  "phone_number": "01712345678",
  "password": "at-least-8-characters"
}
```

Successful response: `201 Created`

```json
{"message":"User registered successfully","user_id":"..."}
```

`name` is optional and is trimmed before storage. Passwords must contain 8–128 characters. Bangladesh mobile numbers are accepted in common local and international forms—such as `01712345678`, `8801712345678`, or `+8801712345678`—and stored in the canonical `+8801XXXXXXXXX` format.

### `POST /login`

Authenticates a registered user and creates a 30-day bearer-token session.

Request body:

```json
{
  "phone_number": "01712345678",
  "password": "at-least-8-characters"
}
```

Successful response: `200 OK`

```json
{
  "access_token": "...",
  "token_type": "bearer",
  "expires_at": "2026-07-18T00:00:00+00:00"
}
```

The access token is returned only in this response. Use it with protected routes as `Authorization: Bearer <access_token>`.

### `POST /generate`

Generates preliminary Bengali veterinary guidance. Authentication is not required.

The endpoint accepts `multipart/form-data` and requires at least one of `info`, `text`, `images`, or `audio` to be present.

| Field | Type | Description |
| --- | --- | --- |
| `info` | text (JSON-encoded string, optional) | Structured intake data collected via the frontend's mandatory form fields — animal age, fever status, and stool/urine status. Sent as a form field whose *value* is a JSON string (see below), since the request as a whole is `multipart/form-data` and cannot carry a nested JSON body directly. |
| `text` | text (optional) | Freeform written description of the animal's condition, in addition to `info` |
| `images` | repeatable file field (optional) | One or more images for visual context |
| `audio` | file (optional) | A Bengali audio recording describing the issue |
| `animal_type` | text (optional) | Optional animal selector value (`cow`, `goat`, `chicken`, or `duck`) used to filter matched disease profiles |

Successful response: `200 OK`

```json
{"response":"AI-generated Bengali veterinary guidance"}
```

#### `info` field format

The frontend now collects three pieces of intake information through a form — age, fever status, and stool/urine status — rather than leaving them to freeform text. This is because the model reliably asks for these three details before it can give an accurate assessment, so they are now captured directly instead of being inferred from prose.

These three values are packaged client-side into a JSON object and sent as the *string value* of the `info` form field:

```json
{
  "age": 3,
  "fever": "উচ্চ তাপমাত্রা",
  "stool_urine": "স্বাভাবিক"
}
```

Example raw multipart body for the `info` field:

```
------WebKitFormBoundaryXXXX
Content-Disposition: form-data; name="info"

{"age": 3, "fever": "উচ্চ তাপমাত্রা", "stool_urine": "স্বাভাবিক"}
------WebKitFormBoundaryXXXX
```

`age` is sent as a JSON number; `fever` and `stool_urine` are sent as Bengali strings drawn from a fixed set of frontend selectbox options (rather than arbitrary free text), which keeps the values consistent for keyword matching. The backend parses this string with `json.loads()` immediately on receipt. If `info` is present but is not valid JSON, the backend returns `400` with a Bengali error message rather than passing malformed data further into the pipeline.

Once parsed into a Python dict, `info` is used in two ways:
- Its values are joined into the combined text used for the disease knowledge-base keyword match (see below), alongside `text` and the audio transcript.
- It is formatted as a `key: value` block and appended to the Gemini prompt as the user's structured intake data, distinct from `text`.

#### What the frontend must now do

The frontend (Streamlit) collects age, fever status, and stool/urine status via explicit form controls (e.g. `st.number_input` for age, `st.selectbox` for fever and stool/urine) rather than a single freeform text box. Before submitting, it JSON-encodes these three values into a single object and sends that object as the `info` field's value alongside the existing `text`, `images`, `audio`, and `animal_type` fields, all within the same `multipart/form-data` request. The request shape and endpoint otherwise remain unchanged — this only affects how `info` is populated and encoded.

Images are base64-encoded and passed to the model. Audio is converted to 16 kHz mono WAV with FFmpeg, transcribed by the local Whisper `small` model, then included with the user's input. 

Before querying the Gemini API, the backend performs a keyword matching step: it combines the parsed `info` values, `text`, and `audio` transcript inputs, then does case-insensitive substring matching against the symptoms list in `Backend/data/disease_knowledge_base.json` (filtering by the requested `animal_type` if provided). Any matching disease entries are formatted in Bengali as a reliable information source block and appended to the prompt to ground the generated response. If no matching diseases are found, the model falls back to its general reasoning but is instructed in the system prompt to explicitly clarify that its advice is a general assessment, not a confirmed diagnosis. The model is prompted to respond only in Bengali, restrict itself to animal-health topics, use clear language, describe likely causes and immediate steps, identify urgent warning signs, and encourage consultation with a veterinarian when appropriate.

### `POST /save-response`

Saves one generated response for the authenticated user.

Required header:

```http
Authorization: Bearer <access_token>
```

Request body:

```json
{"response":"Text of the generated response"}
```

Successful response: `201 Created`

```json
{"message":"Response saved successfully","response_id":"..."}
```

The response is trimmed before storage and must contain 1–50,000 characters.

### `GET /saved-responses`

Returns the authenticated user’s saved responses, newest first.

Required header:

```http
Authorization: Bearer <access_token>
```

Successful response: `200 OK`

```json
{
  "phone_number": "+8801712345678",
  "responses": [
    {
      "response_id": "...",
      "response": "Saved AI guidance",
      "created_at": "2026-07-18T00:00:00+00:00"
    }
  ]
}
```

## Persistence and security

MongoDB contains three collections:

| Collection | Stored information | Indexes |
| --- | --- | --- |
| `users` | Name (or null), canonical phone number, salted password hash, address, email (or null, default null), profile_picture_url (or null, default null), farms (array, default []), creation time | Unique `phone_number` |
| `sessions` | Canonical phone number, SHA-256 token hash, creation and expiry times | Unique `token_hash`; TTL on `expires_at` |
| `saved_responses` | Owner phone number, response text, creation time | Compound `phone_number`, `created_at` index |

Passwords use salted `scrypt` hashes. The database never stores plaintext passwords or bearer tokens. A session is valid until its expiry time; expired sessions are rejected and removed when encountered, while MongoDB’s TTL index removes them automatically in the background.

## Errors and operational behaviour

| Status | Meaning |
| --- | --- |
| `400` | `/generate` received no `info`, `text`, image, or audio input, or the `info` field's value was not valid JSON |
| `401` | Login failed, or a protected request has no valid unexpired bearer token |
| `409` | The phone number already has an account |
| `422` | The request does not match validation requirements |
| `500` | Audio could not be converted or transcribed |
| `502` | Gemini API returned an error while producing a response |


Error responses use FastAPI’s `detail` field. Some operational messages are intentionally written in Bengali so they can be shown directly in the user interface.

## Deployment considerations

- Keep `.env` and database credentials out of version control.
- The application currently has no CORS configuration. A browser client hosted on a different origin will need an explicit CORS policy before it can call the API.
- The default audio and AI pipeline runs locally and can be resource-intensive. Capacity planning should account for concurrent transcription and model-generation requests.
- Validate upload size and file type at the deployment boundary if the service will be exposed publicly.
